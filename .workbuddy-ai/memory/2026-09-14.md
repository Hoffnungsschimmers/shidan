## 第九轮：v0.3.5 —— 无障碍细化

这一版没有新功能，修的都是「视觉上有、非视觉用户拿不到」的信息缺失。
V0.3 的三个既定候选（年度回顾 / 无障碍 / 分享接入时间线）里，先做无障碍。

### 1. 加载中的按钮对屏幕阅读器是一片空白

`MiuixButton` 在 `loading = true` 时把标签**替换**成转圈，
于是按钮的语义内容变成空的 —— 读不出是什么按钮，也不知道正在处理。

修法：语义整体重写。

```kotlin
.clearAndSetSemantics {
    contentDescription = label
    role = Role.Button
    if (loading) stateDescription = "处理中"
    if (active) onClick(label = label) { onClick(); true } else disabled()
}
```

**关键坑**：`clearAndSetSemantics` 会连 `clickable` 的语义一起清掉。
不显式补回 `role` 与 `onClick`（或 `disabled`），按钮会对无障碍服务**直接消失**。
这是「修一个无障碍问题引入另一个」的典型，必须成对写。

### 2. 分段控件读不出哪个被选中

`MiuixSegmented` 用的是 `clickable(role = Role.Tab)` —— 视觉上有滑动的白色指示块，
但选中状态**没有进入语义树**。

修法：容器 `selectableGroup()` + 选项 `selectable(selected, role = Role.Tab)`。
两者**必须配对**，只写一个不会播报「已选中」。
指示块用 `clearAndSetSemantics {}` 排除（纯装饰，否则多读一个空元素）。

### 3. 图表对屏幕阅读器完全不可见

柱状图结构上全是 `Box` 与空 `Text`。改为整体描述：
`「3月 5 次，4月 2 次，…」`。逐柱朗读 12 个数字既冗长，又还原不出趋势。

「去得最多的店」整行拼成一句 `「第 1 名 老王面馆，去过 3 次」` ——
默认逐子元素朗读会把「1」「老王面馆」「3 次」拆成三段互不相关的信息。
这里同样要补回 `Role.Button` 与 `onClick`。

### 4. 其它

- 概览数字带滚动动画，屏幕阅读器可能读到动画中间值 → 锁定最终值播报。
- 照片查看器的 `3 / 9` 会被读成「三 斜杠 九」→ 改为「第 3 张，共 9 张」。
- 比例条、指示块等纯装饰元素全部排除出语义树。

### 5. 大字体

分段控件高度原为固定 46dp，系统字体最大档会裁字。改为**按文字行高反推最小高度**：

```kotlin
val textHeight = with(LocalDensity.current) { labelLineHeight.toDp() }
val segmentHeight = maxOf(SEGMENT_HEIGHT, textHeight + SEGMENT_INSET * 2 + 10.dp)
```

算了一下各档：fontScale 1.0 → 38dp、1.3 → 44dp，都小于 46dp，
所以**常规情况下高度完全不变**，只有 2.0 才撑到 58dp。这个「默认外观不变」
是刻意的 —— 无障碍修复不该顺手改掉所有人看到的样子。

`MiuixButton` 的 `height(54.dp)` 同样改为 `heightIn(min = 54.dp)`：
54dp 是**最小**高度而非固定高度。

### 6. 评估后没做的

- **底部导航栏高度**：64dp 固定，fontScale 2.0 时标签约 57dp，勉强够。
  真要让导航栏长高，`MainContentBottomPadding`（内容区底部留白，104dp 常量）
  也得跟着动态化，牵动三个标签页的 padding。收益小、改动面大，先不做。
- **卡片语义合并**：`MiuixCard` 加 `mergeDescendants` 会让卡片内的照片缩略图、
  编辑/删除按钮对 TalkBack 失效。凡是卡片内有可交互子元素就不能合并，
  而 `MiuixCard` 是通用组件、无法自行判断，因此不加。

### 2. Bug：`wasRestoredFromSavedState()` 恒为 true

四个表单 ViewModel 用同一模式判断销毁时是否回收图片：

```kotlin
override fun onCleared() {
    if (!saved && !wasRestoredFromSavedState()) { photoStore.deleteOwnedPhotos(photoPaths) }
}
private fun wasRestoredFromSavedState() =
    savedStateHandle.contains(KEY_NOTE) || savedStateHandle.contains(KEY_PHOTOS)
```

**问题在时机**：同一个类里的持久化逻辑会把这些 key 写回 `savedStateHandle`：

```kotlin
init {
    viewModelScope.launch {
        _uiState.map { ... }.distinctUntilChanged().collect { savedStateHandle[...] = ... }
    }
}
```

`viewModelScope` 用 `Dispatchers.Main.immediate`，StateFlow 首帧**同步发射** ——
这些 key 在**构造期间**就被写入。等到 `onCleared` 再判断，`contains` 恒为 true，
条件永不成立。

后果：导入图片后放弃表单，文件不回收，变成孤儿文件（要等手动「清理无用文件」，
且需满足 10 分钟存活门槛）。

**修复**：在构造时求值，且**必须声明在 `init` 之前**（Kotlin 属性按声明顺序初始化）。

```kotlin
// 必须在 init 之前
private val restoredFromSavedState: Boolean =
    savedStateHandle.contains(KEY_NOTE) || savedStateHandle.contains(KEY_PHOTOS)
```

四个文件：`AddVisitViewModel`、`EditVisitViewModel`、`AddRestaurantViewModel`、
`EditRestaurantViewModel`。

> 编辑 `EditRestaurantViewModel` 时我把这个块**插重复了三次**（第一次放太靠后、
> 第二次用同样的 old_string 又插了一遍），编译前用 grep 数了一遍才清干净。
> 教训：用 `Edit` 往同一位置插入内容后，先 grep 确认只有一处，再继续。

### 3. 这类 bug 的特征

- **没有任何报错、没有用户可见异常**，只是清理逻辑静默失效；
- 单元测试很难覆盖（需要构造时序 + 协程调度器配合）；
- 只能靠**主动审计删除路径**发现。

因此「删除」相关代码要定期重读，它不会自己暴露问题。
v0.3.3 的换封面误删、本轮的回收失效，都是这么找出来的。

## 第十一轮：v0.3.7 —— 统计聚合可测试化

### 1. 选题理由

用户持续说「继续」，候选清单上的年度回顾与分享接入时间线我都不打算做。
改为补**测试覆盖**，理由很直接：

而现状是 53 个用例全在边角工具函数上（格式化、转换器、结果类型、筛选），
**核心聚合逻辑（统计）零覆盖** —— 因为它直接读系统时钟，根本没法测。

### 2. 问题：读时钟 = 不可测

`FootprintViewModel` 里的统计函数：

```kotlin
private fun List<FootprintEntry>.toMonthlyCounts(): List<MonthlyCount> {
    val current = YearMonth.now()                                   // ← 读时钟
    ...
}
private fun Long.toYearMonth(): YearMonth =
    Instant.ofEpochMilli(this).atZone(ZoneId.systemDefault())       // ← 读时区
```

同一输入在不同日期/时区得到不同结果，测试只能断言「跑得通」。
而这里的边界恰恰最容易写错又最难手工验证：跨年窗口起点、
UTC 的 `2025-12-31 23:00` 落在哪根柱子、排行榜顺序是否稳定。

### 3. 改动

新增 `ui/home/FootprintAggregation.kt`，六个聚合函数抽成**纯函数**，
`today: YearMonth` 与 `zone: ZoneId` 提升为参数。ViewModel 只剩
「读一次时钟 + 组装状态」，明显变短。

**这是「把隐藏依赖变成显式契约」的典型收益**：
测试可固定任意日期与时区，时区行为从隐含变成写明。

### 4. 新增 21 个用例（`FootprintAggregationTest`）

| 分组 | 覆盖 |
| --- | --- |
| 时区 | 月份归属随时区变化；`isInYear` 用指定时区 |
| 月度柱状图 | 空数据仍返回固定 12 个月；窗口从早到晚；窗口外不计入；同月累加；时区决定落在哪根柱；月份数可配置；月份数必须为正 |
| 常去的店 | 次数倒序；次数相同时按 id 升序；上限；空数据 |
| 花费估算 | 只统计指定年份；识别不出跳过而非计零；全识别不出返回 null 而非 0；年份判定受时区影响 |
| 月份分组 | 保持输入顺序；空数据 |

其中「全识别不出返回 null 而非 0」「次数相同时按 id 升序」两条
是**把设计决策锁进测试** —— 以后有人想「简化」成返回 0 或去掉 tie-break，
测试会拦下来。

## 第十二轮：v0.3.8 —— 修复 emoji 截断损坏字符串

### 1. 又一个靠读代码发现的 bug

`MealRepository` 里自由文本的统一入库处理只有一行：

```kotlin
private fun String.normalizeText(limit: Int): String = trim().take(limit)
```

**`take(limit)` 数的是 UTF-16 码元，不是字符。**
增补平面字符（绝大多数 emoji）在 UTF-16 里占**两个**码元，
在截断边界上会被切成半个代理对，产生**非法 UTF-16 字符串**：

```kotlin
"很好吃😋".take(3)   // → "很好吃" + 半个代理对（孤立高代理）
```

后果不是「显示难看」，而是**数据损坏**：

- 入库后读出渲染成 `�`；
- 写进 JSON 备份时孤立代理编码成非法转义，**备份文件可能直接无法解析**；
- 备份/恢复往返一次，原文永久丢失。

**修复**：按 code point 截断，`offsetByCodePoints` 自动跳过完整代理对。
同时把长度上限语义统一为**码点**（一个 emoji 算 1 个字符）。

### 2. 已知近似（刻意不处理）

截断级别是 **code point** 而非**字素簇**。ZWJ 复合 emoji 可能被拆开
（`👨👩👧` → `👨👩`）。视觉不理想，但**仍是合法字符串**，不损坏数据。

字素簇级别需要 `java.text.BreakIterator`，其行为依赖默认 locale，
而三处限制（40/500/2000）在真实输入里几乎不会正好落在 ZWJ 序列中间。
为这点收益引入 locale 依赖不划算 —— **写进代码注释与 CHANGELOG，不藏着**。

### 3. 新增 18 个用例（`MealTextTest`）

核心是这条：**穷举 0..N 每个截断长度，断言结果不含孤立代理**。
它不针对某个具体输入，而是对任意截断位置都成立 —— 这才是修复的真正保障。

其余覆盖：全角空格 U+3000 被 trim、中间空格保留、limit=0、
limit 为负抛异常、emoji 按个数而非码元计数、三个实际上限、
粘贴整段聊天记录静默截断。

### 4. 本机「审计删除路径」之外的第二个例行项

v0.3.3（换封面误删）、v0.3.6（回收失效）是**审计删除路径**发现的；
本轮是**审计字符串处理**发现的。共同点：

> 这类 bug 没有报错、没有用户可见异常，只是数据静默损坏。

已写进 skill：字符串截断、编码、长度计算相关代码也要定期重读。
