### 1. 数据层：花费字段（数据库 v2 → v3）

  （「人均 60 左右」「约 200」无法用整数表达）。
- `AppDatabase.version = 3`；`DatabaseModule.Migration2To3`：
  `ALTER TABLE dining_records ADD COLUMN priceText TEXT NOT NULL DEFAULT ''`。
- **踩坑**：实体必须同时写 `@ColumnInfo(defaultValue = "''")`。否则迁移后的表带
  `DEFAULT ''`、全新安装的表不带，两者不等价，Room 的 schema 校验在老用户升级时

  统一由 `MealRepository.normalizeText(limit)` 做 trim + 截断（截断而非报错，
  超长输入通常来自粘贴）。
- 备份包新增 `priceText`（写 `put`，读 `optString` 取默认），
  **不提升 `FORMAT_VERSION`**，v1/v2 旧备份仍可导入。

### 3. Liquid Glass（真背景模糊）

Compose 的 `Modifier.blur()` 模糊的是自己，不是身后的内容。真正的背景模糊做法：

1. `rememberGraphicsLayer()` 建 layer；
2. 内容容器用 `Modifier.drawWithContent { layer.record(density, layoutDirection, size) { drawContent() }; drawContent() }`
   录制内容（**record 只有 4 参形式**，Compose 1.7.6 没有带默认值的重载）；
3. `layer.renderEffect = RenderEffect.createBlurEffect(r, r, TileMode.CLAMP).asComposeRenderEffect()`
   （只设置一次，**不要放在 draw 回调里**）；
4. 玻璃面板在自己的 `drawBehind` 里 `clipRect { translate(contentOrigin - panelOrigin) { drawLayer(layer) } }`。

- `drawLayer` 在 `androidx.compose.ui.graphics.layer` 包（`GraphicsLayerKt`）。
- `rememberGraphicsLayer` 在 `androidx.compose.ui.graphics`（`GraphicsLayerScopeKt`）。
- API < 31 无 `RenderEffect`，自动降级为「高不透明度着色 + 边缘高光」。
- 玻璃观感三要素：主体着色（≥80% 不透明）、自上而下的透光梯度、顶部折射高光。

### 7. 迁移等价性验证（本机可做，无需设备）

用内存 SQLite 复刻 Room 的校验：

1. 用 `app/schemas/.../2.json` 的 `createSql` 建表 + 插一行老数据；
2. 执行 `Migration2To3` 的 SQL；
3. 用 `3.json` 的 `createSql` 另建一张表；
4. 比对两者 `PRAGMA table_info` 的 name / type / notNull / pk / defaultValue。

结果：**差异为空**，历史行完整（`priceText` 补为 `''`）。
注意 Room 用 `Map<String, Column>` 比较，**列顺序不同不算差异**
（迁移把新列追加在末尾，全新安装的新列在中间）。

### 2. 全屏照片查看器

新增 `ui/components/PhotoViewer.kt`：

- `PhotoViewerState`（`open(paths, index)` / `close()`）+ `rememberPhotoViewerState()` +
  `PhotoViewerHost(state)`。状态拆成「是否可见」与「看哪几张」两个字段：
  关闭时先播淡出、再释放照片列表，否则动画期间内容会先消失只剩一片黑。
- 左右滑动切换（`HorizontalPager`）、双击 1x↔2.5x、放大后单指拖动平移。
- **实现为全屏 Dialog，不是页内浮层**。浮层要求调用方把根容器改成 `Box` 并把查看器
  放在最后一个子节点，而表单页根容器是 `Column`（纵向排列），塞进去会挤占布局。
  Dialog 自带返回键处理与窗口层级，调用位置无所谓。
  `DialogProperties(usePlatformDefaultWidth = false, decorFitsSystemWindows = false)`。
- **不支持双指缩放**：`detectTransformGestures` 会消费**全部**指针事件（含单指拖动），
  挂上它之后 `HorizontalPager` 收不到滑动事件，翻页直接失效。要同时支持必须手写
  `awaitEachGesture` 按指针数量分流，代码量与出错面显著上升且没有真机难以验证。
  改用「双击缩放 + 放大后拖动」这组互不冲突的手势：
  `userScrollEnabled = !zoomed`，拖动的手势检测只在 `scale > 1` 时挂载。
- 接入 6 处：详情页用餐照片与头图、足迹时间线、以及四个表单页的已选照片
  （`SelectedPhoto` 新增 `onPreview` 参数）。

### 3. 主动放弃的一项：从用餐照片设置封面

想过做，**评估后决定不做**。原因是它会引入文件别名：
`restaurants.recommendationPhotoPath` 与 `photos.filePath` 指向同一个文件后，
现有所有删除路径都会出问题 ——

- `MealRepository.updateRestaurant` 换封面时会直接删掉旧封面文件；
- `deleteDiningRecord` 会删掉该记录的全部照片文件；
- `EditRestaurantViewModel.onCleared` 取消编辑时会删掉「非原始封面」的图片。

任一处都会删掉另一处仍在引用的文件。要支持这个功能，必须先把全局不变式改成
「**磁盘文件只在没有任何数据库行引用它时才允许删除**」，并让所有删除路径
统一走一个带引用的守卫。这是一次涉及数据安全的仓库层重构，
不该顺手塞进视觉迭代里。**如果以后要做，必须先做这个重构。**

### 4. 本机环境坑（补充）

- **连续两次调用 Gradle 也会触发那个偶发 R8 报错**。
  `lintDebug && assembleDebug assembleRelease` 这种链式调用失败过两次，

## 第六轮：v0.3.2 —— 统计（足迹 → 时间线 / 统计）

### 1. 从自由文本估算花费

「花费」是自由文本，统计只能估算。新增 `String.parseEstimatedAmount()`，
取文本中**最大**的数字而不是第一个：

| 输入 | 取第一个 | 取最大（实现） |
| --- | --- | --- |
| `128` | 128 | 128 |
| `人均60` | 60 | 60 |
| `3个人吃了240` | 3 ❌ | 240 ✅ |
| `1,280` | 1 ❌ | 1280 ✅ |

- 先移除**千分位逗号**再匹配：`(?<=\d),(?=\d{3})`。不移除的话 `1,280` 会被切成
  `1` 与 `280`，最大值变成 280。
- 已知偏差并**在界面文案中标注**：`30-40` 取 40（偏大）；`人均60` 是单价不是整桌金额。
- 金额展示不保留小数（估算显示小数会制造「很精确」的错觉），超一万改用「万」。
- **一条都识别不出来时显示「还没有能识别的金额」而不是 `¥0`** ——
  后者会被读成「今年没花钱」，而事实是「没有可识别的金额」。

### 2. 统计页

「足迹」页顶部加分段控件「时间线 / 统计」，不加第四个底部标签
（两个视角属于同一批数据，底部保持三个入口）。

内容：概览（今年 / 去过的店 / 累计）、花费估算、最近 12 个月柱状图、
评价分布、去得最多的店 Top 5。

图表约定（写进 `DESIGN_SYSTEM.md`）：

- **横轴固定 12 个月**，以当前月为基准向前推。只画「数据中出现过的月份」会让
  某月没记录时该柱消失、月份间距错乱。
- 有记录的柱最低 6dp，空月份画 3dp 灰柱 —— 「吃过一次」与「一次没吃」必须分得开。
- 12 个月份标签在窄屏会挤成一团：**隔一个显示一个**，最后一个月（当前月）始终显示。
- 空月份不显示 `0`，减少视觉噪音。

同时把评价分布从页面头部移到统计分段：头部在两个分段下都显示，
留在头部会导致切到统计页时同一组数字出现两次。

### 3. 踩坑

- 实现 `parseEstimatedAmount` 时第一版忘了处理千分位逗号，
  测试用例 `1,280` 会失败 —— **先写测试用例再写实现，这次靠它直接暴露了**。
- 偶发 R8 报错本轮又出现一次（累计第 4 次）。重跑即通过。
