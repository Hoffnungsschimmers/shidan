### 3. Liquid Glass（真背景模糊）

Compose 的 `Modifier.blur()` 模糊的是自己，不是身后的内容。真正的背景模糊做法：

1. `rememberGraphicsLayer()` 建 layer；
2. 内容容器用 `Modifier.drawWithContent { layer.record(density, layoutDirection, size) { drawContent() }; drawContent() }`
   录制内容（**record 只有 4 参形式**，Compose 1.7.6 没有带默认值的重载）；
3. `layer.renderEffect = RenderEffect.createBlurEffect(r, r, TileMode.CLAMP).asComposeRenderEffect()`
   （只设置一次，**不要放在 draw 回调里**）；
4. 玻璃面板在自己的 `drawBehind` 里 `clipRect { translate(contentOrigin - panelOrigin) { drawLayer(layer) } }`。

- `drawLayer` 在 `androidx.compose.ui.graphics.layer` 包（`GraphicsLayerKt`）。
- `rememberGraphicsLayer` 在 `androidx.compose.ui.graphics`（`GraphicsLayerScopeKt`）。
- API < 31 无 `RenderEffect`，自动降级为「高不透明度着色 + 边缘高光」。
- 玻璃观感三要素：主体着色（≥80% 不透明）、自上而下的透光梯度、顶部折射高光。

## 第六轮：v0.3.2 —— 统计（足迹 → 时间线 / 统计）

### 1. 从自由文本估算花费

「花费」是自由文本，统计只能估算。新增 `String.parseEstimatedAmount()`，
取文本中**最大**的数字而不是第一个：

| 输入 | 取第一个 | 取最大（实现） |
| --- | --- | --- |
| `128` | 128 | 128 |
| `人均60` | 60 | 60 |
| `3个人吃了240` | 3 ❌ | 240 ✅ |
| `1,280` | 1 ❌ | 1280 ✅ |

- 先移除**千分位逗号**再匹配：`(?<=\d),(?=\d{3})`。不移除的话 `1,280` 会被切成
  `1` 与 `280`，最大值变成 280。
- 已知偏差并**在界面文案中标注**：`30-40` 取 40（偏大）；`人均60` 是单价不是整桌金额。
- 金额展示不保留小数（估算显示小数会制造「很精确」的错觉），超一万改用「万」。
- **一条都识别不出来时显示「还没有能识别的金额」而不是 `¥0`** ——
  后者会被读成「今年没花钱」，而事实是「没有可识别的金额」。

### 2. 统计页

「足迹」页顶部加分段控件「时间线 / 统计」，不加第四个底部标签
（两个视角属于同一批数据，底部保持三个入口）。

内容：概览（今年 / 去过的店 / 累计）、花费估算、最近 12 个月柱状图、
评价分布、去得最多的店 Top 5。

图表约定（写进 `DESIGN_SYSTEM.md`）：

- **横轴固定 12 个月**，以当前月为基准向前推。只画「数据中出现过的月份」会让
  某月没记录时该柱消失、月份间距错乱。
- 有记录的柱最低 6dp，空月份画 3dp 灰柱 —— 「吃过一次」与「一次没吃」必须分得开。
- 12 个月份标签在窄屏会挤成一团：**隔一个显示一个**，最后一个月（当前月）始终显示。
- 空月份不显示 `0`，减少视觉噪音。

同时把评价分布从页面头部移到统计分段：头部在两个分段下都显示，
留在头部会导致切到统计页时同一组数字出现两次。

### 3. 踩坑

  测试用例 `1,280` 会失败 —— **先写测试用例再写实现，这次靠它直接暴露了**。

## 第七轮：v0.3.3 —— 修复换封面误删图片 + 删除引用守卫 + 封面复用 + 深色模式

### 1. 修复一个既有的数据丢失 bug（v0.2.0 起就存在）

`EditRestaurantViewModel.onPhotosPicked` 在导入新封面时会**立即删除上一张**：

```kotlin
val obsolete = state.photoPaths.filterNot { it == newCover }
state.copy(photoPaths = listOf(newCover), ...).also { photoStore.deleteOwnedPhotos(obsolete) }
```

但**表单首次加载时 `photoPaths` 就是数据库当前使用的封面**。于是：

1. 打开某家已有封面的店 → `photoPaths = [原封面]`；
2. 导入新图 → 旧封面文件在导入的**那一刻**被删除；
3. 用户按返回放弃编辑 → 数据库仍指向原封面，文件已经没了。

结果：封面**永久空白**。`onCameraPhoto` 有同样的问题。

**修复**：把回收规则抽成纯函数 `reclaimableFormPhotos(formPhotoPaths, originalCoverPath,
recordPhotoPaths, keep)` —— 只有「本次导入、且当前未被选中」的可以回收。
四处（`onPhotosPicked` / `onCameraPhoto` / `useRecordPhotoAsCover` / `onCleared`）
统一走它，并配 9 个单元测试（第一个就是上述路径的回归用例）。

> 这个 bug 是靠**逐个检查删除路径**发现的，不是靠报错。教训：
> 「删除」相关代码必须主动审计，它不会自己暴露。

### 2. 重构：磁盘文件删除统一走引用守卫

新增 `MealRepository.deleteUnreferencedFiles()`，把全局不变式明确为
**「磁盘文件只在没有任何数据库行引用它时才允许删除」**。

仓库内 6 处删除调用全部改走守卫（`updateRestaurant` / `addDiningRecord` /
`updateDiningRecord` / `deleteDiningRecord` / `deleteRestaurant` / `replaceAllData`）。

代价是每次删除读一次全表路径集合（`getAllPhotoPaths()` + `getRestaurantCoverPaths()`），
个人数据量下可忽略。**必须在事务提交之后调用**，否则会读到未提交的中间状态。

### 3. 新增：从用餐照片设置封面

`EditRestaurantScreen` 新增「或从用餐照片里选」一栏。DAO 的

### 5. 踩坑

- Lint 报了 `UseKtx`：`preferences.edit().putString(...).apply()` 应改用
  core-ktx 的 `preferences.edit { putString(...) }`（默认就是 apply）。

## 第八轮：v0.3.4 —— 分享卡片

### 1. 实现

餐厅详情页每条用餐记录新增「分享」按钮 → 弹预览 → 确认后渲染成竖版图片（3:4）
交给系统分享面板。

**为什么必须先预览再分享**：

1. 卡片是**渲染**出来的，照片会被裁成竖版，裁剪结果无法凭想象预判；
2. Compose 只能录制**已经绘制过**的内容 —— 把卡片藏起来（alpha 0 / 尺寸 0 /
   移出屏幕）都会录到空白，显示在对话框里才有内容可录。

### 2. 技术要点（已写进 skill）

- `GraphicsLayer` 录制 + `layer.toImageBitmap()`（**挂起函数**，等渲染管线处理完当前帧）
  → `asAndroidBitmap()`。
- 分享图写在 `cacheDir/shared/`，**不写 `files/photos/`**：后者是用户数据，
  混进去会让设置页的「照片占用空间」失真，还会被 `cleanupOrphanPhotos` 反复清理。
- `res/xml/file_paths.xml` 补了 `cache-path`（原先只有 `files-path`），
  否则 `getUriForFile` 会抛 `IllegalArgumentException`。
- Intent 三要素：`ACTION_SEND` + `type="image/png"` + `EXTRA_STREAM` +
  **`FLAG_GRANT_READ_URI_PERMISSION`**（少了它接收方读不出内容）。
  用 `createChooser` 而非直接 `ACTION_SEND`。
- 用 PNG 不用 JPEG：卡片含文字与圆角，JPEG 块效应在文字边缘很明显。
- 文件名带时间戳：接收方持有 URI 期间文件必须有效，覆盖同名会让它拿到半张图。
- 渲染期间禁用分享按钮，防连点生成多张图。

### 3. 踩坑

- `private const val` 写在**类体里**（companion object 之外）编译报错
  `Const 'val' is only allowed on top level, in named objects, or in companion objects`。
  常量必须放进 companion。
- `StateFlow.asStateFlow()` 忘了 import，报 `Unresolved reference`。
- **构建耗时异常（23 分钟）且后台任务丢失**：APK 实际已生成（用 `ls -la` 看时间戳确认），
  只是任务跟踪断了。教训：构建卡住时先查产物时间戳，不要盲目重跑。
- Gradle 输出里出现二进制内容时 `grep` 会报 `Binary file (standard input) matches`，
  用 `grep -a` 强制按文本处理。
