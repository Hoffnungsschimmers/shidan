## 第二轮：系统性审查（发现-解决-验证闭环）

在上一轮优化后，对全量代码做了一次主动审查，按严重度分级修复。

### P0（并发安全 / 数据丢失）

1. **`pendingPhotoCleanup` 线程不安全**：`MealRepository` 是 `@Singleton`，
   内部却用普通 `mutableMapOf` 承接表单临时照片，多个 ViewModel 协程并发读写会
   结构损坏。改用 `ConcurrentHashMap`，并用 `remove()` 的原子性实现
   “取出即清空”（`takePendingPhotos`）。
2. **进程被杀即丢失全部表单输入**：两个表单 ViewModel 都只有内存态。
   引入 `SavedStateHandle`（`AddRestaurantViewModel` / `AddVisitViewModel`
   构造函数第 3 个参数），持久化 `name/address/photos/date/verdict/dishes/note`；
   `AddVisitViewModel` 的 `restaurantId` 也走 `SavedStateHandle`。
   Compose 侧把 `pendingCameraFile: File?` 换成
   `pendingCameraPath: String?` + `rememberSaveable`（`File` 不可序列化）。

### P1（内存 / 竞态 / 数据一致性 / 发布安全）

3. **Bitmap 过早回收**：`PhotoStore.writeBitmap` 里直接 `recycle()`，
   调用方仍持有引用，可能触发 `IllegalStateException: Cannot draw recycled bitmap`。
   改由 `importSingle` 的 `finally` 统一回收。
4. **孤儿清理误删在拍照片**：`deleteOrphanPhotos` 无差别删除未被引用的文件，
   会干掉相机刚拍、尚未入库的中间文件。加 `ORPHAN_MIN_AGE_MS = 10 分钟` 时间闸门。
5. **保存按钮 check-then-act 竞态**：先读 `_uiState.value` 判断再 `launch`，
   快速双击可产生重复餐厅。改为 `updateAndGet` 原子状态跃迁
   （`isSaving` 抢占失败即直接 return）。
6. **删除链路事务边界错误**：`deleteDiningRecord` 在事务外同步餐厅状态，
   观察者会短暂看到“记录已删但仍是已用餐”。把 `syncRestaurantStatusInTransaction`
   移入事务内；`updateRestaurant` 也改为事务提交成功后才删旧封面文件。
7. **Release 包未混淆未压缩**：`isMinifyEnabled = false` 且 `proguard-rules.pro` 为空。
   开启 `isMinifyEnabled` + `isShrinkResources` 并补齐 keep 规则
   （Room / Hilt / Coil / 枚举名，枚举名是落库编码不能混淆）。
   效果：Release APK 18.5MB → 1.78MB（约 −90%），并生成 `mapping.txt`。

### P2（性能 / 可访问性 / 体验）

8. **Coil 隐式尺寸**：为 `SelectedPhoto` 补 KDoc，说明必须显式指定解码尺寸，
   否则全尺寸解码易 OOM。
9. **图片无障碍**：详情页多张用餐照片 `contentDescription` 完全相同，
   改 `itemsIndexed` 输出“用餐照片，第 N 张，共 M 张”。
10. **SavedStateHandle 逐键写入**：初版在 init 中收集整个 state，每次输入都写 Bundle。
    改为投影出 `PersistedForm` 并 `distinctUntilChanged()` 过滤。
11. **表单返回键误删照片**：`onCleared` 增加
    `wasRestoredFromSavedState()` 守卫，进程恢复场景不执行清理。

### 新发现的坑（重要）

**1. Gradle 单元测试类路径缺陷（环境问题，与代码无关）**

`testDebugUnitTest` 报 `ClassNotFoundException ... at initializationError`，**全部**测试类
都无法装载（不是断言失败）。根因：AGP 的 `bundleDebugClassesToRuntimeJar` 产物
（`app/build/intermediates/runtime_app_classes_jar/debug/bundleDebugClassesToRuntimeJar/classes.jar`）
没被放进测试工作进程 classpath，测试看不到主源码集的类。

尝试过的无效修法：在 `build.gradle.kts` 里用 `doFirst { classpath += files(jar) }`
（太晚，快照已完成）以及配置期 `classpath += files(mainClassesJar)` + `dependsOn(...)`
（仍无效，已回退删除）。

**有效验证方式**：直接用 JDK 跑同一批测试，33 个用例全部通过：

```bash
"$JDK17/bin/java.exe" -cp "<asm输出目录>;<runtime_app_classes_jar/.../classes.jar>;<junit>;<kotlin-stdlib>;<hamcrest>" \
  org.junit.runner.JUnitCore <测试类全名...>
```

已在 README「已知环境问题」中记录。

**2. R8 `classes.dex 另一个程序正在使用此文件`**

`minifyReleaseWithR8` 会因残留守护进程锁定 `app/build/intermediates/dex/release/` 而失败。
解决：`./gradlew.bat --stop` → 删除该目录 → 重新构建。

**3. Kotlin DSL 两处作用域陷阱**

- `android { }` 块内 `java` 被 AGP 扩展遮蔽，`java.util.Properties()` 报
  `Unresolved reference: util`。解决：文件顶部 `import java.util.Properties`。
- `signingConfigs` **必须声明在 `buildTypes` 之前**，否则
  `signingConfigs.getByName("release")` 报 `SigningConfig with name 'release' not found`。
